# v2.2.x → v2.4.x migration guide

**Estimated time:** 15–30 minutes (AIM catalog step only)  
**Complexity:** Low–medium  
**Risk level:** Medium if `hardwareFamilies` is not set before sync

There is **no v2.3 release**. This guide covers upgrades from any v2.2.x
cluster-forge tag directly to v2.4.x.

> Replace `<domain>` with the cluster domain everywhere below.

## Before you start

- [ ] kubectl **admin** access to the cluster
- [ ] ArgoCD UI + admin creds — `https://argocd.<domain>`
- [ ] Gitea UI + admin creds — `https://gitea.<domain>`
- [ ] Cluster is on **v2.2.x** (for example v2.2.2)
- [ ] You know the cluster hardware family: `instinct`, `epyc`, `radeon`, or `cpu`

### What changed (EAI-8160)

The `aim-cluster-model-source` chart no longer supports the legacy behavior where
an **empty** `hardwareFamilies` list installed the full generic catalog. From
v2.4 onward:

- **`hardwareFamilies` is required** — at least one family must be set.
- An empty list **fails Helm render** (`templates/guard.yaml`), blocking sync.
- Only sources for the listed families are rendered; ArgoCD **prune** removes
  any `AIMClusterModelSource` not in the manifest.

This guard protects brownfield clusters: without it, an upgrade with empty
families would render zero sources and prune would delete the entire AIM catalog.

Chart reference: [`sources/aim-cluster-model-source/README.md`](../../sources/aim-cluster-model-source/README.md)

## Step 1 — Set `hardwareFamilies` in cluster-values (do this first)

Open Gitea → `cluster-org/cluster-values` → `values.yaml` → **Edit**.

Add or update under `apps:` **before** bumping `clusterForge.targetRevision`:

```yaml
apps:
  aim-cluster-model-source:
    valuesObject:
      hardwareFamilies:
        - instinct   # pick one or more: instinct, epyc, radeon, cpu
```

| Cluster hardware | Typical value |
|---|---|
| MI300X / Instinct GPU | `[instinct]` |
| EPYC CPU inference | `[epyc]` |
| Radeon GPU | `[radeon]` |
| Generic CPU (RC catalog) | `[cpu]` |

**Brownfield Instinct clusters** that previously relied on the empty default
(install-all legacy catalog) should set **`instinct`** explicitly — that is the
closest equivalent catalog under the new family-gated templates.

Commit and push. Wait for the umbrella `cluster-forge` app to pick up the
change (or sync it manually in ArgoCD).

> **Do not skip this step.** Syncing v2.4 chart sources with empty
> `hardwareFamilies` fails render and leaves the app OutOfSync with a template
> error — it does not silently keep the old catalog.

---

## Step 2 — Bump cluster-forge to v2.4.x

In the same `cluster-values/values.yaml`, update:

```yaml
clusterForge:
  targetRevision: v2.4.0   # use the actual v2.4 tag at release time
```

Commit and push. ArgoCD rolls out the new chart revision.

If the `aim-cluster-model-source` app shows a Helm template error mentioning
`hardwareFamilies must be set`, return to **Step 1** — the family list is still
missing or empty in cluster-values.

---

## Step 3 — Sync and verify AIM model sources

```bash
# Sources present for your family(ies)
kubectl get aimclustermodelsource -A

# ArgoCD app healthy
kubectl get application aim-cluster-model-source -n argocd
```

Expected behavior after sync:

- Sources **not** in the new family manifest are **pruned** (removed from the cluster).
- Sources for your selected family(ies) remain or are recreated.
- Discovery repopulates `AIMClusterProfile` objects (~1–2 minutes).

If deploy profiles look stale after the catalog change, re-trigger discovery:

```bash
kubectl delete aimclustermodelsource --all
# Sync the aim-cluster-model-source app in ArgoCD, then:
kubectl get aimclustermodelsource
kubectl get aimclusterprofiles -A
```

---

## Step 4 — Smoke-check the deploy UI

- [ ] `kubectl get aimclustermodelsource` — sources **Ready**, `MODELS > 0`
- [ ] `kubectl get aimclusterprofiles -A` — profiles **Ready**, hardware matches cluster
- [ ] Deploy UI lists models without a “not supported on your hardware” banner

---

## Upgrade policy (additive manifest, prune)

The chart manifest is additive **per family**: each sync installs only sources
for families listed in `hardwareFamilies`. With ArgoCD prune enabled, sources
removed from the manifest (or from a de-listed family) are deleted from the
cluster. Plan catalog changes accordingly; redeploy AIM workloads if their
source was pruned.
